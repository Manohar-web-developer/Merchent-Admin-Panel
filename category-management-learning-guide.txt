7. RECURSIVE TREE LOGIC (VERY IMPORTANT)
--------------------------------------------------------------------------------

Hierarchy Concept:
Furniture (Level 0 - Main Category)
 └── Living Room (Level 1 - Sub Category)
      └── Sofas (Level 2 - Sub Sub Category)
           └── 3 Seater Sofa (Level 3 - Child Category)

WHAT IS RECURSION IN REACT?
Recursion ka matlab hai jab ek component apne andar KHUD KO WAPAS CALL (render) karta hai, jab tak condition satisfy hoti rahe.

Kaise kaam karta hai actual code me?

`CategoryTreeItem.jsx` ka structure dekho:
```javascript
export default function CategoryTreeItem({ item, level = 0 }) {
  const hasChildren = item.children && item.children.length > 0;

  return (
    <div>
      {/* 1. Current Category Node render karta hai */}
      <span>{item.name}</span>

      {/* 2. Agar children exist karte hain, to KHUD KO DOBAAR CALL KARTA HAI */}
      {hasChildren && (
        <div className="ml-6">
          {item.children.map((childItem) => (
            <CategoryTreeItem item={childItem} level={level + 1} />
          ))}
        </div>
      )}
    </div>
  );
}
```

PARENTS vs CHILDREN DATA STRUCTURE:
Nested Tree Data Object Format:
```json
{
  "id": "cat-1",
  "name": "Furniture",
  "children": [
    {
      "id": "cat-1-1",
      "name": "Living Room",
      "children": [
        {
          "id": "cat-1-1-1",
          "name": "Sofas",
          "children": []
        }
      ]
    }
  ]
}
```

BACKEND FLAT DATA FORMAT (parentId reference):
Database me list aksar flat hoti hai:
1. `_id`: "101", `name`: "Furniture", `parentId`: null
2. `_id`: "102", `name`: "Living Room", `parentId`: "101"
3. `_id`: "103", `name`: "Sofas", `parentId`: "102"

Frontend Array to Tree Helper Function (Future conversion logic):
```javascript
function buildTree(categories, parentId = null) {
  return categories
    .filter(item => item.parentId === parentId)
    .map(item => ({
      ...item,
      children: buildTree(categories, item._id) // Recursive call
    }));
}
```

8. TREE KI CONNECTOR LINES
--------------------------------------------------------------------------------

Tree visual connector lines (`│`, `├──`, `└──`) Tailwind CSS and absolute positioning se bani hain.

`CategoryTreeItem.jsx` me connector lines logic:
```html
{level > 0 && (
  <>
    <!-- Vertical Line (Up to Down) -->
    <span
      className={cn(
        "absolute -left-4 top-0 border-l border-slate-200 pointer-events-none",
        isLast ? "h-4" : "h-full"
      )}
    />
    <!-- Horizontal Branch Line (Left to Right) -->
    <span className="absolute -left-4 top-4 w-3 border-t border-slate-200 pointer-events-none" />
  </>
)}
```

EXPLANATION:
1. `border-l` (Border Left): Vertical line banata hai.
2. `border-t` (Border Top): Horizontal branch line (`—`) banata hai.
3. `absolute -left-4`: Left side parent margin space me lines ko position karta hai.
4. `isLast ? "h-4" : "h-full"` (CRITICAL FIX):
   - Agar current node branch ka LAST CHILD hai (`isLast === true`), to vertical line middle height (`h-4` i.e. 16px) par rukh jaati hai, taaki neeche faltu extra line na khinche (`└──`).
   - Agar niche aur siblings hain (`isLast === false`), to vertical line poori height (`h-full`) cover karti hai taaki agle sibling tak line continue ho (`├──`).
5. `level > 0`: Level 0 (Root categories like Furniture) par lines nahi banti. Level 1 se lines visible hoti hain.

13. CATEGORY DATABASE SCHEMA
--------------------------------------------------------------------------------

Recommended MongoDB / Mongoose Schema Definition:

```javascript
const categorySchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true,
    },
    slug: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
    },
    description: {
      type: String,
      default: "",
    },
    parentId: {
      type: mongoose.Schema.Types.ObjectId,
      ref: "Category",
      default: null, // null means Top-Level / Root Category (e.g. Furniture)
    },
    status: {
      type: String,
      enum: ["Active", "Inactive"],
      default: "Active",
    },
    isDeleted: {
      type: Boolean,
      default: false,
    },
  },
  { timestamps: true }
);
```

`parentId: null` vs `parentId: "64b1f..."` DIFFERENCE:
- `parentId: null`: Pehle level ki Main Category hai (Jaise "Furniture" ya "Electronics"). Iska koi parent nahi hai.
- `parentId: "Furniture_ID"`: Sub Category hai (Jaise "Living Room", jiska parent "Furniture" hai).
- `parentId: "Living_Room_ID"`: Sub-Sub Category hai (Jaise "Sofas", jiska parent "Living Room" hai).

14. CRUD FLOW (FULL-STACK JOURNEY)
--------------------------------------------------------------------------------

1. CREATE FLOW:
   User fills Add Category Form -> Click Submit -> Axios.post('/api/category/add', formData) 
   -> Express Route -> CategoryController.create() -> Category.save() in MongoDB -> Return Success Response -> Refresh Frontend State.

2. READ FLOW:
   Category Page Mounts -> useEffect runs -> Axios.get('/api/category/all') 
   -> Controller queries `Category.find({ isDeleted: false })` -> Returns JSON Array -> `setCategories(data)` -> UI re-renders Tree & Table.

3. UPDATE FLOW:
   User clicks Edit button -> Form auto-fills category details -> User changes Name/Parent -> Click Save -> Axios.put('/api/category/edit/123') 
   -> Controller updates DB `Category.findByIdAndUpdate()` -> Returns updated object -> State updates in UI.

4. DELETE FLOW:
   User clicks Trash button -> Confirmation Dialog -> Axios.delete('/api/category/delete/123') 
   -> Controller soft deletes in MongoDB -> Frontend filters out deleted ID from local state array -> UI updates table.

16. PAGINATION (DYNAMIC)
--------------------------------------------------------------------------------

Formula for Backend MongoDB Pagination:
- `page`: Current Page number (e.g. Page 2)
- `limit`: Items per page (e.g. 10)
- `skip`: `(page - 1) * limit`  => `(2 - 1) * 10 = 10` items skip

Backend Query:
```javascript
const categories = await Category.find()
  .skip((page - 1) * limit)
  .limit(limit);

const totalRecords = await Category.countDocuments();
const totalPages = Math.ceil(totalRecords / limit);
```

Frontend receive karta hai: `{ data: [...], page: 2, totalPages: 3, totalRecords: 24 }`.

21. IMPORTANT FINAL SECTION: REAL DEVELOPER MINDSET
--------------------------------------------------------------------------------

QUESTION: "AGAR MAIN YE CATEGORY SYSTEM KHUD SE BANATA TO MUJHE KYA SOCHNA CHAHIYE?"

Senior Software Engineer Mindset & Problem Breakdown Strategy:

1. Data Structure First (Pehle UI mat socho, Data Model Socho):
   - Direct frontend layout likhna start mat karo. Pehle paper par draw karo ki Category 
     ka Data Structure kaisa hoga: Single flat list with `parentId` approach better hai 
     ya deeply nested objects array? (Flat list with `parentId` in MongoDB is always 
     best for scale!).

2. Single Source of Truth:
   - UI me Tree View aur Table View dono alag tareeke se dikh rahe hain, lekin DATA SOURCE 
     dono ka SAME DATABASE ARRAY hona chahiye. Ek place par update ho to tree aur table 
     dono automatic refresh hone chahiye.

3. Scalability & Performance:
   - Agar database me 10,000 categories ho jayein, to poora tree ek ساتھ DOM me load 
     karna browser hang kar dega. Isiliye "Lazy Loading" (Branch expand hone par 
     API call karke child categories lana) ka system sochna padta hai.

4. User Experience (UX):
   - Action buttons (Edit/Delete) intuitive hone chahiye.
   - Parent Category Delete karne se pehle Confirm Modal aana chahiye ki "Is category ke 
     andar 45 sub-categories aur 120 products hain, kya aap sach me delete karna chahte hain?".

5. Step-by-step Incremental Building:
   - Direct sab kuch ek baar me banane ke bajaye system ko 5 stages me break karo:
     Stage 1: Static UI (Completed)
     Stage 2: Simple Read API (View Table)
     Stage 3: Create Category Form
     Stage 4: Tree Rendering
     Stage 5: Search & Pagination
