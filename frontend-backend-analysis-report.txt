ISSUE #1
========

Frontend File: /Users/mac/Desktop/Merchent-Admin-Panel/src/pages/AddBrands.jsx
Relevant Function / Line: Lines 82 & 95 (handleSubmit function)

Backend API / Function: BrandCreate (POST brand/create) & BrandUpdate (PUT brand/update/:id)

Exact Mismatch or Problem:
Frontend checks if (res.data.res) to verify API success, but backend response does not contain a 'res' property. Backend returns { message: "...", result: {...} }.

Frontend Currently Kya Kar Raha Hai:
`if (res.data.res)` condition check kar raha hai after axios call.

Backend Actually Kya Expect Kar Raha Hai / Bhej Raha Hai:
Backend response structure:
`return res.status(201).json({ message: "Brand Created Successfully", result });`
`return res.status(201).json({ message: "Brand Updated Successfully", result });`

Why This Causes a Problem:
`res.data.res` hamesha `undefined` return karega. `if (res.data.res)` condition false hogi.

Impact:
Critical. Brand database me create ya update ho jata hai, lekin frontend me toast notification (toast.success) show nahi hota aur user page list (`/products/brands`) par redirect nahi hota. User ko lagta hai request fail ho gayi.

Recommended Fix:
`if (res.data.res)` ki jagah `if (res.data.result || res.status === 201)` check karo.

Priority: Critical

ISSUE #2
========

Frontend File: /Users/mac/Desktop/Merchent-Admin-Panel/src/pages/AddBrands.jsx
Relevant Function / Line: Lines 36-40 (useEffect details fetch)

Backend API / Function: BrandDetails (POST brand/details/:id) & BrnadSchema

Exact Mismatch or Problem:
Frontend checks if res.data.data.status === "1" (String comparison), whereas Mongoose Schema stores status as a Boolean (true/false).

Frontend Currently Kya Kar Raha Hai:
```javascript
if (res.data.data.status === "1") {
  setStatus(true);
} else {
  setStatus(false);
}
```

Backend Actually Kya Expect Kar Raha Hai / Bhej Raha Hai:
BrnadSchema me status field: `status: { type: Boolean, default: true }`.
Backend JSON response me `status: true` (Boolean) bhejta hai, string `"1"` nahi.

Why This Causes a Problem:
`true === "1"` JS me strict comparison hamesha `false` evaluate hota hai.

Impact:
High. Jab bhi kisi active brand ko edit karne ke liye khola jayega, form load hote hi status toggle automatically "Inactive" select ho jayega. Edit karke save karne par active brand automatically Inactive me convert ho jayegi unless user manual toggle kare.

Recommended Fix:
`setStatus(Boolean(res.data.data.status))` ya `setStatus(res.data.data.status === true)` use karo.

Priority: High

Backend API / Function: BrandDelete (PUT brand/delete)

Impact:
Medium. Double API calls cause unnecessary network traffic, backend DB query overhead, and race conditions.

Recommended Fix:
`useEffect` ke andar directly `fetchBrands()` ko invoke karo aur duplicate `axios.post` call remove karo.

Exact Mismatch or Problem:
Backend `BrandCreate` me logo filename save karta hai (`dataSave.logo = logo.filename`), jabki `BrandUpdate` me logo filepath save karta hai (`dataSave.logo = logo.path`).

Frontend Currently Kya Kar Raha Hai:
Frontend `baseurl + res.data.data.logo` concatenating string format expects consistent relative filename.

BrandCreate: `dataSave.logo = logo.filename` (e.g. "1724280000000.png")
BrandUpdate: `dataSave.logo = logo.path` (e.g. "public/uploads/1724280000000.png" or "uploads/1724280000000.png")

Why This Causes a Problem:
Brand update hone ke baad DB me logo property ka format change ho jaega. `baseurl + logo` frontend me image URL break kar dega (`http://localhost:5000/uploads/public/uploads/1724280000000.png`).

Impact:
High. Logo images broken/unrenderable in table and edit form preview after brand update.

Recommended Fix:
Backend inconsistency fix ki jarurat hai ya frontend side par string format sanitize/normalize karke image render kijiye.

Priority: High
